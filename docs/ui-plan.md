**状态**：方案稿 v2（2026-11-17 按用户决定修订），等你确认后再写 UI 代码。本文不含实现，只定结构、流程与规范。

**v2 修订（2026-11-17）**：
①free 的「更多能力」改为**每个功能一条占位入口**（名称 + 一句话 + 统一「暂未开放」弹窗），界面不出现 owner/完整版/获取方式；

**基线**：现有 `main` 的 3 个 Tab（媒体库 / 提取 / 我的）、Compose Material3、`BackgroundLayer` 壁纸背景、`UiKit` 组件；

## 1. 信息架构

### 1.1 顶层：仍然 3 个 Tab（不加重型 Tab）

```
┌─────────────────────────────────────────┐
│                                         │
│              内容区                     │
│                                         │
├─────────────────────────────────────────┤
│   📚 媒体库      🔗 提取      👤 我的    │
└─────────────────────────────────────────┘
```

理由：重型能力（定时/Agent/授权/AI）是**低频但重**的操作，放第 4、5 个 Tab 会把"提取→播放"这条主路径挤窄。
它们收进「我的」的二级页，从"更多能力"进入；博主批量与提取同源，入口留在**提取页**（少一层跳转）；
批量导出是免费的本机功能，入口留在**媒体库**。

### 1.2 二级页树

```
我的
├─ 账号与安全            （免费）
├─ 外观与背景            （免费）
├─ 播放与下载设置        （免费）
├─ 更多能力              （free：6 条占位；full：下面 5 条真实入口）
│   ├─ 定时抓取          full
│   ├─ 提取 Agent        full
│   ├─ 平台授权          full
│   ├─ 失败上报          full（查看）
│   └─ AI 视频重建       full
├─ 诊断与反馈            （免费；full 多"上报历史"）
├─ 关于 / 协议           （免费）
└─ 联系作者              （免费）
```

两处入口**搬位置**（2026-11-17 决定）：

- **博主批量**：真实入口从「更多能力」移到**「提取」页**（Tab 2），仅 full 显示，仍走 `OwnerGate` 接缝。
- **批量导出**：入口在**媒体库**（多选顶栏、播放列表、类别详情），免费功能，free 与 full 都有；详见 `docs/export-plan.md`。

## 2. 全局规范

### 2.1 尺寸与栅格

| 项 | 值 |
|---|---|
| 设计基准 | 360 × 800 dp（小屏下限 320 dp 宽） |
| 页面左右边距 | 16 dp（卡片内 12–16 dp） |
| 卡片圆角 | 16 dp；按钮 12 dp；Chip 全圆 |
| 列表行高 | 单行 56 dp、双行 72 dp、三行 88 dp |
| 底部导航 | 80 dp（含手势区 `WindowInsets.navigationBars`） |
| 触控目标 | ≥ 48 × 48 dp |
| 间距刻度 | 4 / 8 / 12 / 16 / 24 / 32 |

### 2.2 五种页面状态（每页都必须有）

```
① 加载中     骨架屏（3–5 行灰块），不用转圈盖全屏
② 空          图标 + 一句说明 + 一个主操作（"去提取"）
③ 错误        可读原因 + 重试按钮 + "复制诊断信息"
④ 无网络      顶部细条（不遮挡内容）+ 自动重试倒计时
⑤ 未开放        功能名 + 一句话（这项功能做什么）+ 统一弹窗「暂未开放」；
                 不写日期、不承诺、不出现 owner/完整版/获取方式/购买
```

文案规则：不出现 HTTP 状态码；`403` 说"被平台拒绝"，`412` 说"请求太频繁，稍后再试"，
`429` 说"操作太频繁"；技术细节只进"复制诊断信息"。

### 2.3 颜色（沿用 Material3 + 现有主题）

| 语义 | 浅色 | 深色 | 用途 |
|---|---|---|---|
| primary | `#6750A4` | `#D0BCFF` | 主按钮、选中态 |
| surface | `#FEF7FF` | `#141218` | 页面底 |
| surfaceVariant | `#E7E0EC` | `#49454F` | 卡片、输入框 |
| error | `#B3261E` | `#F2B8B5` | 失败、删除 |
| 成功/进行中 | `#2E7D32` | `#81C784` | 任务完成、同步成功 |
| 警告 | `#ED6C02` | `#FFB74D` | 配额将满、需重新授权 |

**壁纸背景兼容**：`BackgroundLayer` 开启时，卡片不透明度由 `LocalCardAlpha` 控制（现为 0.86），
文字一律用 `onSurface`，**不硬编码白色**；图片/封面加 8% 黑色遮罩保证对比度 ≥ 4.5:1。

### 2.4 排版

`displaySmall` 36 / `headlineSmall` 24 / `titleLarge` 22 / `titleMedium` 16 / `bodyLarge` 16 / `bodyMedium` 14 / `labelSmall` 11。
数字用等宽（进度、字节、时间），避免跳动。

free 的「更多能力」是一个**列表页**：每个功能一条占位入口（名称 + 一句话），与 full 的同名功能一一对应。

| 占位条目（名称） | 一句话（这项功能做什么） |
|---|---|
| 博主主页批量提取 | 按博主主页一次提取多个作品 |

「联系作者获得」这类字样，也不写日期、不承诺版本、不做版本对比。
数据仍放在 `PlaceholderCatalog`（APK 内静态数据，改文案要重新构建）。

> 现状差异（P4 待办）：仓库里的 `PlaceholderCatalog` 目前是「多设备同步 / 云端协助提取 / 博主批量 / 定时抓取 /
> Agent / AI」6 条，与上表不一致——多两条、少「平台授权」「失败上报」。实现时按上表对齐，并保持 free 侧
> 只有静态文案、没有任何重型实现。

### 3.4 博主批量 · 新建（full，重点页，见 §5 流程）

入口：**提取页顶部「博主批量」pill**（仅 full 渲染，走 `OwnerGate.BatchExtract`）。

```
┌──────────────────────────────────────┐
│ ← 博主批量                           │
│ ┌──────────────────────────────────┐ │
│ │ 粘贴主页链接 / 分享文案 / 昵称…  │ │
│ └──────────────────────────────────┘ │
│ [自动识别] [B 站] [抖音]   [粘贴]    │
│                                      │
│ 抓取范围  ( • ) 最近 N 条            │
│           (   ) 全部                 │
│           (   ) 指定日期区间         │
│                                      │
│ N = [ 20 ] 条   （直接输入，1–9999） │
│                                      │
│ 日期区间（北京时间）                 │
│ [ 2026-10-01 ] ～ [ 2026-10-31 ]     │
│ ⓘ 按北京时间的自然日计算；不跟随手机 │
│                                      │
│ 包含置顶  [ ✓ ]   仅列表不下载 [ ]   │
│ 类型  ( • ) 音频  (   ) 视频         │
│                                      │
│ ┌──────────────┐                     │
│ │   读取列表   │                     │
│ └──────────────┘                     │
│                                      │
│ ── 预览（已加载 200 / 1200）────────  │
│ 👤 碧诗 · 1200 条 · 预计 5.2 GB      │
│ ☑ 全选（全部 1200 条）  已选 12      │
│ ☑ [置顶] 标题…        03:24  12 MB   │
│ ☑ 标题…               08:11  38 MB   │
│ ☐ 标题…               01:02   5 MB   │
│            … 继续下滑再加载 200 条   │
│                                      │
│ ┌──────────────────────────────┐     │
│ │  创建任务（12 条 · 210 MB）  │     │
│ └──────────────────────────────┘     │
└──────────────────────────────────────┘
```

参数区的三条硬规则：

1. **数量用数字输入框**：`N = [ 20 ]`，直接键 1–9999，**不提供 5/10/20/50/100 固定档位**，
   **不做「自动夹到 100」**；非数字或 0 在输入框下给行内提示，不静默改值。
2. **日期区间用日期选择器**（两个日期按钮 → 系统日期选择器，显示 `yyyy-MM-dd`），
   下发的就是 `since` / `until` 的日期字符串，**服务端按北京时间（UTC+8）解释**，与手机时区无关；
   结束日期取当日 23:59:59。开始 > 结束时就地提示，不提交。
3. **预览列表必须能承载「全部」**：用 `LazyColumn` 虚拟滚动 + 分页（每页 200 条，滚到底继续读），
   **不允许一次性把上千条塞进普通 `Column`**。全选的语义是「服务端返回的全部条目」，
   分页只影响渲染；标题栏显示「已加载 200 / 1200」，避免用户以为只有 200 条。


可用时：项目列表 → 上传/从媒体库选 → 分析（生成描述）→ 编辑描述 → 生成（队列）→ 产物播放/保存。

### 3.11 诊断与反馈

沿用现有：一键导出诊断包（脱敏：不含 Cookie、不含登录名）、反馈表单（可带截图）、复制诊断 ID。

### 3.12 外观与背景

沿用现有：壁纸开关、卡片不透明度滑杆（0.60–1.00）、跟随系统深色 / 强制浅色 / 强制深色、动效开关。

| 位置 | free | full |

## 5. 博主批量：完整流程（重写重点）

### 5.1 与服务端的契约（P2 已实现）

| 步骤 | 接口 |
|---|---|
| 读列表 | `POST /v2/creators/preview`（`mode`=window/all/date_range/latest_n、`include_pinned`） |
| 建任务 | `POST /v2/creators/jobs` |
| 看进度 | `GET /v2/creators/jobs/{id}`、`/items?state=pending` |
| 领取/回传 | `GET /items?state=pending` + `POST /items/{video_id}/state` |
| 控制 | `pause` / `resume` / `cancel` / `retry` |
| 抖音兜底 | 手机抓列表 → `POST /items:import` |

### 5.2 状态机

```
                    ┌──────────────┐
   输入博主 ──→ 解析 ─→│  preview     │
                    └──────┬───────┘
                           │ 用户勾选 + 确认
                           ▼
                    ┌──────────────┐  建任务  ┌──────────┐
                    │  creating    │────────→│ pending  │
                    └──────────────┘          └────┬─────┘
                                                   │ 手机开始领取
                                                   ▼
                    ┌──────────┐  暂停   ┌──────────────┐
                    │ paused   │←───────│   running    │
                    └────┬─────┘        └───┬──────┬───┘
                         │ resume           │      │ 全部条目终态
                         └─────────────────→│      ▼
                                            │  ┌──────────┐
                       取消 ───────────────→│  │   done   │
                                            ▼  └──────────┘
                                      ┌──────────┐
                                      │cancelled │
                                      └──────────┘
```

条目状态：`pending → downloading → (done | failed | skipped)`。
**关键规则**：置顶作品带 `is_pinned` 角标但**不插队**；排序始终按发布时间倒序。

### 5.3 端到端时序（B 站）

```
用户            App(full)                服务端                   B 站
 │  粘贴链接      │                        │                        │
 │──────────────→│ POST /creators/preview │                        │
 │               │───────────────────────→│ wbi 签名 + 访客Cookie  │
 │               │                        │───────────────────────→│
 │               │  43 条 + 预计字节      │←───────────────────────│
 │  勾选 12 条    │←───────────────────────│                        │
 │──────────────→│ POST /creators/jobs    │                        │
 │               │───────────────────────→│ 建任务 + 落 cursor     │
 │               │   job_id               │                        │
 │               │←───────────────────────│                        │
 │               │ GET /items?state=pending（每 2s 或用户下拉）     │
 │               │───────────────────────→│                        │
 │               │  待下载条目             │                        │
 │               │←───────────────────────│                        │
 │               │ 本地解析 + 下载（本机） │                        │
 │               │ POST /items/{id}/state │                        │
 │               │───────────────────────→│ 更新计数                │
 │               │ GET /jobs/{id}         │                        │
 │               │───────────────────────→│ 进度/剩余              │
```

下载**在手机上执行**（服务端只列列表、记账）。若用户在服务端库模式下选择"存服务器"，
则改为 `POST /v2/extract` + `GET /v2/extraction-jobs/{id}` 轮询，进度语义一致。

### 5.4 每一步的界面与失败分支

| 步 | 界面 | 失败分支 |
|---|---|---|
| 1 输入 | 输入框 + 平台 Chip + 粘贴 | 识别不出 → 行内提示"这看起来不是主页链接"，不弹窗 |
| 2 解析 | 按钮转"正在读取…"，禁用重复点击 | `404` → "没有找到这个博主"；`403/412` → "b 站要求登录，去授权" + 按钮；`429` → "太频繁，60 秒后再试"（带倒计时） |
| 3 预览 | 博主卡片 + 条目勾选 + 预计空间；`LazyColumn` 虚拟滚动 + 分页 200 条 | 0 条 → 空态；只有置顶 → 提示"该博主只有置顶作品"；翻页失败 → 保留已加载部分 + 行内重试 |
| 4 参数 | 范围（最近 N / 全部 / 日期区间）/ 数量数字输入框 / 置顶 / 类型 | 数量非数字或 0 → 行内提示，**不静默夹取**；超出可读范围 → 提示"该 UP 只有 43 条"，不替用户改数字；日期倒置 → 就地提示，不提交 |
| 5 建任务 | 按钮显示"创建任务（12 条 · 210 MB）" | 磁盘不足（服务端存时才判）→ 提示可改"只存元数据" |
| 6 进行 | 进度条 + 计数 + 剩余时间 | 单条失败不打断；连续 5 条失败 → 自动暂停并提示"可能 Cookie 失效" |
| 7 完成 | 摘要：成功 11 / 失败 1 / 跳过 0 | 失败条目可"重试/跳过/复制链接" |
| 8 中断 | 退到后台/杀进程 | 任务在服务端仍是 `running/paused`；重进 App 从 `/jobs` 恢复视图 |

**断点续跑**：App 不保存游标，一切以服务端 `cursor.start` 为准；重装 App 也能接着下。

### 5.5 抖音分支（手机列）

```
输入抖音主页 → 服务端 preview 返回 403 Argus
   │
   ├─ 若已授权且服务端装了浏览器桥接 → 正常流程
   └─ 否则 → 界面明确切换为"手机列"模式：
        ① 提示条：抖音在服务器侧被风控，改为手机读取列表（不消耗服务器额度）
        ② App 内 WebView 打开主页，抓 posts 接口 → 得到条目
        ③ 用户勾选 → POST /items:import 入库（去重）
        ④ 后续下载与其他平台一致
```

这条分支必须在 UI 上**说明为什么**，不能只是"加载失败"。

### 5.6 并发与限速（UI 侧）

- 同时下载 2 条（可设 1–3），其余排队；失败重试 2 次、指数退避 2s/6s。
- 每条约 0.5 s 间隔，避免同 IP 触发 B 站限流（服务端矩阵已实测：连续搜索会 412）。
- 前台服务（`PlaybackService` 同款）跑下载，通知栏显示总进度与"暂停"。

### 5.7 空/错/边界清单（供实现时逐条勾）

- [ ] 链接是单条视频而不是主页 → 引导到提取页
- [ ] 博主 0 作品 / 全部已删除
- [ ] 只能读到置顶（`total=1`）
- [ ] 数量 > 可读范围（`start > total`）→ "范围超出，该 UP 只有 43 条"（只提示，不改用户填的数字）
- [ ] 数量输入非数字 / 0 / > 9999 → 输入框下行内提示，按钮禁用，不静默夹取
- [ ] 日期区间开始晚于结束 → 就地提示，不提交；跨时区手机 → 仍按北京时间解释并显示说明
- [ ] 「全部」预览：1200 条只渲染已加载页（LazyColumn），滚动继续加载；全选作用于全部而不仅是已加载
- [ ] 任务进行中退出 App → 重进恢复
- [ ] 任务进行中断网 → 顶部细条 + 自动重试，不弹窗
- [ ] 磁盘不足 → 建任务前预估就拦（服务端存）/ 下载中拦（本机存）
- [ ] Cookie 过期（连续失败）→ 自动暂停 + "去授权"
- [ ] 同一博主重复建任务 → 提示"已有进行中的任务，去查看"

## 6. 适配

### 6.1 屏幕尺寸

| 场景 | 处理 |
|---|---|
| 320 dp 小屏 | 卡片内边距降到 12 dp；"预计 210 MB"与"12 条"换行；按钮全宽 |
| 360–420 dp 常规 | 基准布局 |
| ≥ 600 dp（平板/折叠展开） | 媒体库改 2 列；批量页左列表右详情（`ListDetailPaneScaffold`）；对话框限宽 480 dp |
| 横屏 | 播放页全屏视频 + 右侧信息栏；批量页保持单列（避免行过长） |
| 折叠态 | 跟随 `WindowSizeClass`，不做自定义断点 |

### 6.2 字体缩放（最多 200%）

- 全部用 `sp`，禁止 `dp` 写字；标题最多 2 行 `maxLines`，超出省略。
- 按钮文字放大后允许换行（`heightIn(min = 48.dp)` 不写死高度）。
- 进度条与角标用 `labelSmall`，放大后隐藏次要信息（如"剩余时间"）。

### 6.3 手势与系统栏

- `enableEdgeToEdge()`；列表底部 `contentPadding` 加 `navigationBars` + 80 dp，避免被导航条盖住。
- 返回手势：子页统一 `BackHandler`；批量任务进行中按返回 → 提示"任务在后台继续"（Snackbar，不拦截）。
- 输入法：批量页输入框获得焦点时 `imePadding()`，按钮随之上移。

### 6.4 无障碍

- 所有图标按钮有 `contentDescription`；进度条有 `stateDescription`（"12 / 20，60%"）。
- 颜色不作为唯一信息载体：状态同时用图标 + 文字（✓/⏳/✗/○）。
- 触控目标 ≥ 48 dp；对比度 ≥ 4.5:1（壁纸开启时用卡片不透明底保证）。

## 7. 深色模式与背景

| 项 | 规则 |
|---|---|
| 跟随方式 | 默认跟随系统；`外观与背景` 可强制浅/深 |
| 主题来源 | `GetMediaTheme(darkTheme=…)`，Material3 `darkColorScheme` |
| 壁纸 | 深色下壁纸自动加 40% 黑色遮罩（现有 `MotionBackground` 行为保留） |
| 卡片 | 深色 `surfaceVariant` + 不透明度 0.86；**不硬编码白/黑** |
| 图片 | 封面在深色下加 8% 黑遮罩，避免亮图刺眼 |
| 状态色 | 深色用 `#81C784`（成功）/`#FFB74D`（警告）/`#F2B8B5`（错误），不用浅色的深色调 |
| 对比度 | 所有文字/背景组合在两种主题下都过 4.5:1（实现时用 Compose 的 `contrastRatio` 自测一遍） |
| 系统栏 | 深色下状态栏图标浅色；`WindowInsetsControllerCompat` 随主题切换 |

**回归检查**：每页在"浅色 / 深色 / 深色+壁纸 / 浅色+壁纸"四种组合下各截一张图，作为 P4 验收附件。
